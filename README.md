# PR Analyzer

A learning project exploring AI-assisted pull-request review: compare a code change against its stated intent and report possible correctness issues with code evidence.

## Current status

The project currently contains a Pydantic experiment that validates input dictionaries and an example JSON review response. There is no LLM integration or Git/PR collection yet. The example response is handwritten, not generated by a model.

## Run the current experiment

Requires Python 3.12.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scr/pr-analyzer/models.py
```

The script prints a valid input, an expected validation error for an integer where a string is required, and the fields of a validated example review response.

Pydantic validates structure and types; it does not establish that a review finding is correct.

## Planned MVP

- Accept a change requirement, a diff, and relevant Java code/tests.
- Ask a hosted LLM for a structured review.
- Validate the report and check its supporting evidence.
- Evaluate three cases: a clear bug, a correct change, and insufficient context.
- Add Git/PR collection once the local review experiment is useful.

The analysis core will be Python. A Spring Boot service may later handle PR collection, authentication, or analysis history if those responsibilities justify a separate service.

## First evaluation examples

For a requirement to reject payment on already-paid orders without charging again:

1. Charge before the paid-status check: identify the supported ordering problem.
2. Check before charging: recognize the visible scenario is satisfied without inventing a bug.
3. Delegate to an unseen method: ask for its implementation rather than infer behavior from its name.
